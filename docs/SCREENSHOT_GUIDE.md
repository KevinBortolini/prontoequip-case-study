# Fictional screenshot guide

This guide describes optional future English captures from an isolated fictional demonstration. The README now contains owner-supplied operational screenshots sanitized under separate instructions; those preserve the original Portuguese UI and are not fictional-data captures. The recipes below were not used to create them. For a future demo, capture only the actual application in isolation; do not recreate its screens in an image editor or use a live account.

## Isolation and English display text

Use a separate disposable app installation and independently configured development backend containing only invented records. Do not duplicate an existing app-data directory, production database, private configuration, account session or photo library. The current application is not a standalone offline demo: its authentication and catalog need a safe backend. Until that environment is explicitly prepared and verified, do not capture these views from the operational system.

The current UI contains Portuguese text. An isolated presentation copy must translate visible labels, validation messages, status text and any report headings to English without changing the original application. Label every image **Fictional demonstration data** in its caption. Use generic text branding rather than inherited logos until asset permissions are confirmed. If an English isolated copy is unavailable, supply captures privately for review; do not present edited translations as original application output.

## A coherent invented scenario

Use a fictional company named **Northstar Tool Lab**, an operator named **Morgan Reed**, and a customer named **Aster Workshop**. Create five active fictional equipment records: DEMO-001, DEMO-002 and DEMO-003 available; DEMO-004 rented; DEMO-005 under review. Counts must come from those records, not modified screenshot pixels.

The rented/review states must be established through valid demo operations, including required evidence, not by editing production data. Use synthetic equipment drawings or plain demonstration objects with no visible people, addresses, serial numbers or vendor/customer paperwork. Do not copy real signatures or identity documents. Leave optional personal-identifier fields empty; stop if a workflow requires one until a safe fixture is agreed.

## Capture and privacy review

Use native app-only screenshots with notifications disabled and account/browser/desktop content excluded. Do not show login credentials, developer overlays, service addresses, device identifiers, remote IDs, private file paths, external share recipients or personal folders. Preserve readable controls; use a second detail crop rather than scaling a tall screenshot into illegible text.

Supply original captures privately for visual and metadata review. Only approved exports should later be placed in `docs/screenshots`. Remove metadata such as author, device, GPS and comments, reopen the exported files, and recheck both pixels and metadata. The review for any future fictional captures remains separate from the completed review of the operational screenshots now in the README.

Optional PDF previews must be generated solely from the same fictional demo, checked for report/document metadata and labelled **PDF preview**, separately from application screenshots. No NFC, camera, signature, share-sheet or physical-device success should be inferred merely from these four images.
